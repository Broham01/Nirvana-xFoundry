# Integration changes (Nirvana ↔ xFoundry)

Append-only. Add a dated line in **both** repos whenever either side changes something the other depends on: an API route, a field read across the boundary, the snapshot or spec format, the gate, or a rule in [CONTRACT.md](CONTRACT.md). Newest first. Say which side changed and what the other side must do, if anything.

- 2026-10-24 · both · `xfoundry.environment/1` gains optional `networks[].internet` (xFoundry ADR 0007): an outbound-only egress gateway (a pod that masquerades out of the cluster network, private ranges blocked), VPC policy routes to it at priority 29000, and a DNS server by DHCP. Additive; the spec stays `/1` and the contract version stays 2. xStage's catalog sets it (on by default for most blueprints), and the environment page offers "Turn on internet". Other side: none beyond pulling.
- 2026-10-23 · both · A second, older worker on the same token failed a job with a `cloud_init` spec. xFoundry's worker now sends `host`, `pid` and `code` (a hash of the spec schema it knows) in its check-in `info` and refuses to start while another worker holds `.xfoundry/worker.lock`; xStage counts overlapping worker processes per token (`copies` on the workers list) and warns when there is more than one. Additive; contract version stays 2.
- 2026-10-23 · both · Environment lifecycle (xStage ADR 0020): pause sends jobs with every VM group powered off; reset queues the rebuild after its destroy succeeds; an expired `lifecycle.ttl` queues a destroy. Every job still becomes a plan a person approves. xFoundry adds optional `vms[].cloud_init` (user, SSH keys, a SHA-512 crypt `password_hash`, packages) to `xfoundry.environment/1`; xStage's catalog writes it. Additive; contract version stays 2. Other side: none beyond pulling.
- 2026-10-22 · both · Status members may carry `detail` (optional, at most 500 characters): why a VM or appliance is not ready. Additive; contract version stays 2. xStage shows it on the environment page.
- 2026-10-21 · both · Contract version 2: the console. xStage gains live updates for browsers (`/api/v1/events`), environments and jobs, and four token routes for the xFoundry worker (claim a job, read it, report progress, report environment status) with scopes `jobs:read`, `jobs:write`, `environments:status`. xFoundry gains `xfoundry worker`. Other side: xFoundry must use only these routes and states (done in the same change); a worker needs a new token with the new scopes (tokens made before today lack them).
- 2026-10-21 · both · Nirvana is renamed Nirvana xStage (repo `Broham01/Nirvana-xStage`); xFoundry's repo is `Broham01/Nirvana-xFoundry`. Contract wording and links updated; no route, scope, field, format or setting changed (`NIRVANA_URL`, `NIRVANA_TOKEN`, `NIRVANA_DIR` keep their names). Other side: none beyond pulling.
- 2026-10-21 · Nirvana · The Kubernetes planner models Kube-OVN `Vpc` (no longer partial) and flags VPC routing changes. xFoundry: none; closes ADR 0002 item 7.
- 2026-10-20 · both · Contract v1 written down: [CONTRACT.md](CONTRACT.md) and `contract.json`, with contract tests in both repos. Open item: `power: half` differs between the apps.
- 2026-10-20 · Nirvana · Service tokens, cluster-scoped custom resources, namespace annotations, KubeVirt/Multus/Kube-OVN planning (Nirvana ADR 0013, PR #1). xFoundry: none; this is what ADR 0002 asked for.
- 2026-10-20 · xFoundry · Idempotency keys derived from the whole request after Nirvana refused a reused key (xFoundry ADR 0002).
